参数允许您提示用户输入一个或多个值，这些值将传递到构建中。例如，您可能有一个项目允许用户上传包含待测试二进制文件的 zip 文件来按需运行测试。这可以通过在此处添加一个 文件参数 来实现。
或者您可能有一个发布软件的项目，并希望用户输入发布说明，与软件一起上传。这可以通过在此处添加一个 多行字符串参数 来实现。

每个参数都有一个 名称 和某种类型的 值 ，具体取决于参数类型。这些名称-值对将在构建启动时作为环境变量导出，从而允许构建配置的后续部分（例如构建步骤）访问这些值，例如使用 ${PARAMETER_NAME} 语法（在 Windows 上为 %PARAMETER_NAME% ）。
这也意味着此处定义的每个参数都应具有唯一的 名称 。

当项目被参数化时，通常的 立即构建 链接将被替换为 使用参数构建 链接，用户将被提示为每个定义的参数指定值。如果他们选择不输入任何内容，则构建将使用每个参数的默认值启动。

如果构建是自动启动的（例如由 SCM 触发器启动），则将使用每个参数的默认值。

当参数化构建在队列中时，尝试启动同一项目的另一个构建只有在参数值不同，或者启用了 必要时执行并发构建 选项时才会成功。

有关此功能的更多信息，请参阅 参数化构建文档 。
