定义逻辑表达式，用于确定哪些代理可以执行此项目的构建。针对每个可用代理的名称和标签测试此表达式时，结果将为 true 或 false 。如果表达式的计算结果为 true ，则该代理将被允许执行此项目的构建。

如果此项目应始终在特定代理或内置节点上构建，则可以分别输入代理名称或 built-in 。

但通常情况下，应避免在此处使用代理的 名称 ，而应使用代理的 标签 。如每个代理的配置页面以及主节点的 系统配置 页面所述，标签可用于表示代理运行的操作系统、CPU 架构或任何其他特性。
使用标签可以避免在添加、移除或重命名代理时重新配置此处输入的标签表达式。

标签表达式可以很简单，只需输入单个 标签 或 代理名称 ，例如 android-builder 或 linux-machine-42 。
您也可以使用各种 运算符 来创建更复杂的表达式。

支持的运算符

支持以下运算符，按优先级从高到低排列：
(expression)
括号 — 用于显式定义表达式的结合性
!expression
NOT — 取反；表达式 expression 的结果 不得 为 true
a && b
AND — 两者 表达式 a 和 b 都必须为 true
a || b
OR — 任一 表达式 a 或 b 为 true 即可
a -> b
“蕴含”运算符 — 等价于 !a || b 。
例如， windows -> x64 可以理解为“如果使用 Windows 代理，则该代理 必须 是 64 位的”，同时仍允许此项目在 没有 windows 标签的任何代理上执行，无论它们是否也具有 x64 标签
a <-> b
“当且仅当”运算符 — 等价于 a && b || !a && !b
例如， windows <-> dc2 可以理解为“如果使用 Windows 代理，则该代理 必须 位于数据中心 2；但如果使用非 Windows 代理，则 不得 位于数据中心 2”

注意事项

  • 所有运算符均为左结合，即 a -> b -> c 等价于 (a -> b) -> c 。
  • 如果标签或代理名称包含可能与运算符语法冲突的字符，可以用引号括起来。
    例如， "osx (10.11)" || "Windows Server" 。
  • 表达式可以不使用空格编写，但建议包含空格以提高可读性；Jenkins 在计算表达式时会忽略空格。
  • 不支持使用通配符（如 * 或 ? ）或正则表达式匹配标签或代理名称。
  • 空表达式的结果始终为 true ，即匹配所有代理。

示例

built-in
此项目的构建只能在内置节点上执行
linux-machine-42
此项目的构建只能在名称为 linux-machine-42 的代理上执行（或者任何恰好拥有名为 linux-machine-42 标签的机器）
linux || macos
此项目的构建可以在具有 linux 标签 或 macos 标签的任何代理上执行（假设运行 Linux 和 macOS 的代理已分配了相应的标签）。请注意，分隔符是 || ，而不是逗号
windows && jdk9
此项目的构建只能在已安装 Java 开发工具包版本 9 的任何 Windows 代理上执行（假设安装了 JDK 9 的代理已被赋予 jdk9 标签）
postgres && !vm && (linux || freebsd)
此项目的构建只能在 Linux 或 FreeBSD 代理上执行，前提是它们 不是 虚拟机，并且已安装 PostgreSQL（假设每个代理都有适当的标签 — 特别是，在虚拟机中运行的每个代理都必须具有 vm 标签，才能使此示例按预期工作）
