选中此选项后，此项目的多个构建可以并行执行。

默认情况下，同一时间只能执行一个项目的单个构建，任何其他启动该项目构建的请求都将保留在构建队列中，直到第一个构建完成。
这是一个安全的默认设置，因为项目通常需要对某些资源（如数据库或硬件设备）进行独占访问。

但如果启用此选项，并且有足够可用的构建执行器来处理此项目，则此项目的多个构建将并行执行。如果在任何时候没有足够可用的执行器，则任何进一步的构建请求将照常保留在构建队列中。

启用并发构建对于执行耗时较长的测试套件的项目非常有用，因为它允许每个构建包含更少量的更改，同时总周转时间会减少，因为后续构建无需等待之前的测试运行完成。
此功能对于参数化项目也很有用，这些项目的各个构建执行（取决于所使用的参数）可以彼此完全独立。

每个并发执行的构建都在其自己的构建工作区中进行，与其他任何构建隔离。默认情况下，Jenkins 会在工作区目录名称后附加 “ @<num> ”，例如 “ @2 ”。
可以通过在启动 Jenkins 时设置 hudson.slaves.WorkspaceList Java 系统属性来更改分隔符 “ @ ”。例如，” hudson.slaves.WorkspaceList=- “ 会将分隔符更改为连字符。
有关设置系统属性的更多信息，请参阅 网站 。

但是，如果启用 使用自定义工作区 选项，则所有构建将在同一个工作区中执行。因此需要谨慎操作，因为多个构建可能最终会同时修改同一目录。
