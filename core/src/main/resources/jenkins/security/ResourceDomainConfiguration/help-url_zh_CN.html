Jenkins 会提供许多可能由不受信任的用户创建的文件，例如项目工作区中的文件或归档构件。当未定义资源根 URL 时，Jenkins 将以 HTTP 头 Content-Security-Policy（“CSP”）提供这些文件。默认情况下，该头被设置为一个禁用许多现代 Web 功能的值，以防止跨站脚本（XSS）和其他针对访问这些文件的 Jenkins 用户的攻击。虽然 CSP 头的具体值可由用户配置（甚至可以禁用），但这样做需要在安全性和功能性之间进行权衡。

如果定义了资源根 URL，Jenkins 将把对用户创建的资源文件的请求重定向到以此处配置的 URL 开头的 URL。这些 URL 不会设置 CSP 头，从而允许 JavaScript 和类似功能正常工作。为使此选项按预期工作，需满足以下约束和注意事项：

  • 资源根 URL 必须是对请求进行正确处理时，Jenkins URL 的有效替代选择。
  • 必须设置 Jenkins URL，并且它必须与此资源根 URL 不同（实际上，需要不同的主机名）。
  • 设置后，Jenkins 将仅通过资源根 URL 提供资源 URL 请求。所有其他请求都将收到 HTTP 404 Not Found 响应。

一旦正确设置了此 URL，Jenkins 将把对工作区、归档构件以及通常由用户生成的内容的类似集合的请求重定向到以资源根 URL 开头的 URL。资源 URL 将包含一个编码了该路径、为其创建 URL 的用户以及创建时间的令牌，而不是像 job/name_here/ws 这样的路径。这些资源 URL 访问静态文件时，就好像 是为其创建该 URL 的用户自己在访问这些文件一样：如果该用户访问这些文件的权限被移除，相应的资源 URL 也将不再有效。 这些 URL 在过期之前无需身份验证即可供任何人访问，因此共享这些 URL 类似于直接共享文件。

安全注意事项

身份验证

资源 URL 不需要身份验证（用户将没有针对资源根 URL 的有效会话）。与其他用户（甚至缺乏 Jenkins 整体/读取权限的用户）共享资源 URL 将使该用户能够访问这些文件，直到 URL 过期。

过期

资源 URL 默认在 30 分钟后过期。过期的资源 URL 会将用户重定向到其等效的 Jenkins URL，以便用户在必要时可以重新进行身份验证，然后重定向回新的资源 URL，该 URL 将再有效 30 分钟。如果用户具有有效的 Jenkins 会话，这通常对用户是透明的。否则，他们将需要再次向 Jenkins 进行身份验证。但是，在浏览带有 HTML 框架的页面（如 Javadoc 站点）时，登录表单无法在框架中显示。在这些情况下，用户需要重新加载顶层框架才能使登录表单出现。

要更改资源 URL 过期的速度，请将系统属性 jenkins.security.ResourceDomainRootAction.validForMinutes 设置为所需的分钟值。较早的过期可能会使这些 URL 更难使用，而较晚的过期则会增加未经授权的用户通过授权用户共享的 URL 获得访问权限的可能性。

真实性

资源 URL 对 URL、为其创建的用户及其创建时间戳进行编码。此外，此字符串包含一个 HMAC 以确保 URL 的真实性。这可以防止攻击者伪造 URL 以使他们能够像其他用户一样访问资源文件。
