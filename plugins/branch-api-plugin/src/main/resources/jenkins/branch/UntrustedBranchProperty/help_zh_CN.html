表示该分支包含来自未对仓库具有写入权限的开发人员的代码更改。

此类代码可能包含恶意更改，因此此标志可作为信号，允许 Jenkins 中的其他插件设置更高程度的隔离以保护构建基础设施，并禁用具有副作用的操作，例如部署到服务器。

可信与非可信区分变得重要的一些示例：

  • GitHub 拉取请求应被视为非可信，因为它们可以由任何用户创建。
  • 类似 trunk、branches、tags、sandbox 的 Subversion 分支结构可能将 trunk、branches、tags 视为可信，而将 sandbox 视为非可信， 其中 Subversion 权限允许任何经过身份验证的用户对 sandbox 具有写入权限， 但允许项目团队提交到所有四个位置。
  • 在仅由员工和承包商处理代码的闭源代码开发中，没有分支需要标记为非可信， 因为每次提交都来自一组已知人员。
